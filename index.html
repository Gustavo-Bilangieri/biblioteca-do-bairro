    Apontamentos

    O que ficou por trás do código

    06 · Os quatro erros do código original
    1. getItem("leitura") devolve texto, não um array — falta JSON.parse.
    2. setItem("leitura", lista) grava [object Object] — falta JSON.stringify.
    3. if (tema == true) nunca é verdadeiro: o que está guardado é o texto "escuro".
    4. dados.nome rebenta na primeira visita, porque JSON.parse(null) dá null.
    const lista = ler("biblioteca:leitura", []);        // 1
lista.push("Os Lusíadas");
guardar("biblioteca:leitura", lista);                // 2

const tema = localStorage.getItem("biblioteca:tema");
if (tema === "escuro") document.body.classList.add("escuro");   // 3

const dados = ler("biblioteca:leitor", null);        // 4
saudacao.textContent = `Olá, ${dados?.nome ?? "visitante"}`;
    01 · Espreitar o armazenamento

    No separador Aplicação das DevTools aparecem as chaves desta origem — agora são biblioteca:tema, biblioteca:leitura, biblioteca:visitas e as restantes. localStorage.length diz quantas são e cada site só vê as suas. Os cookies ficam na mesma secção.

    02 · Onde guardar cada coisa

    Tema escuro → localStorage (preferência pequena, permanente). Sessão de login → cookie HttpOnly (o servidor precisa dela, o JavaScript não a deve ler). Passo de um formulário → sessionStorage (só neste separador). Mil capas offline → IndexedDB (ficheiros e muito espaço). Reservas → servidor (são partilhadas por todos).

    04 · Prever o resultado 
    localStorage.getItem("n")              // "20"  (o valor é substituído e vem sempre texto)
localStorage.getItem("n") + 5          // "205" (concatena, não soma)
Boolean(localStorage.getItem("ativo")) // true  (o texto "false" é verdadeiro)
localStorage.getItem("Ativo")          // null  (as chaves distinguem maiúsculas)
localStorage.length                    // 2     ("n" e "ativo")
    12 · Auditoria de privacidade

    tema → aceitável, preferência inofensiva. token → a evitar: qualquer script o lê, um XSS leva-o; usar cookie HttpOnly. leitor com NIF → arriscado: guardar só o nome, o resto no servidor. desconto → a evitar: o utilizador edita o valor, quem decide é o servidor. passo em sessionStorage → aceitável, é temporário. palavraPasse → nunca.
